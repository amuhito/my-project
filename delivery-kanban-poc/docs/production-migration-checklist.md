# 個人PoCから社内本番への移行チェックリスト

このドキュメントは、`delivery-kanban-poc` を個人 AWS 環境の PoC から、社内運用可能な本番環境へ移行するための確認項目です。

## 1. アカウントと権限

- [ ] 部署または会社管理の AWS アカウントを新規作成し、個人アカウントと分離する
- [ ] ルートユーザーは保管用途に限定し、MFA を必須化する
- [ ] IAM ユーザー直利用をやめ、`IAM Role` 中心に統一する
- [ ] デプロイ専用ロール（CI/CD 用）を作成し、最小権限を適用する

## 2. ネットワークと公開方式

- [ ] 本番リージョンを確定する（例: `ap-northeast-1`）
- [ ] 公開方式を確定する（Lightsail 継続または ECS/Fargate へ移行）
- [ ] 独自ドメインと HTTPS 証明書を設定する
- [ ] アクセス制御方針（認証必須、必要に応じて IP 制限）を定義する

## 3. 認証とセキュリティ

- [ ] 初期 `admin` 運用を廃止し、正式な管理者アカウントを発行する
- [ ] パスワードポリシー（文字数、複雑性、変更ルール）を定義する
- [ ] 機密情報を平文環境変数から `AWS Secrets Manager` または `SSM Parameter Store` へ移行する
- [ ] AWS アクセスキーを棚卸しし、不要キー削除と定期ローテーションを運用化する

## 4. データとバックアップ

- [ ] 本番 DB の方針を確定する（SQLite 継続可否、必要なら RDS へ移行）
- [ ] 自動バックアップ（日次、世代管理）を設定する
- [ ] リストア手順を文書化し、実地で復元テストを行う
- [ ] データ保持期間と削除ルールを定義する

## 5. 監視と運用

- [ ] アプリログとアクセスログを集約し、追跡できる状態にする
- [ ] 監視項目（死活、5xx、レイテンシ、CPU、メモリ）を定義する
- [ ] 通知先（メールまたは Slack）を設定する
- [ ] 障害時の一次対応フロー（担当、初動時間）を決める

## 6. 配布とデプロイ

- [ ] GitHub ブランチ保護を設定する（PR 必須、レビュー必須）
- [ ] 本番デプロイを CI/CD で実行できるようにする
- [ ] ロールバック手順（前バージョンへ戻す）を整備する
- [ ] リリース判定チェックリストを固定化する

## 7. 体制とガバナンス

- [ ] システム所有者、運用責任者、障害連絡先を明確化する
- [ ] 社内利用規程（利用範囲、取り扱いデータ）を明文化する
- [ ] 監査証跡の保存期間を定義する
- [ ] 月次コストレビューの担当と実施日を決める

## 8. カットオーバー

- [ ] ステージングで本番同等テストを完了する
- [ ] 本番初期ユーザー登録と権限設定を完了する
- [ ] 本番リリースを実施する
- [ ] リリース後 1 週間は監視を強化し、日次で確認する
